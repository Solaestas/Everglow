# 任务系统初版功能清单

本清单用于确定初版完成边界、归类修正点和记录验收结果。运行环境已确认覆盖单机、多人和子世界；下面的功能取舍是面向快速收尾的建议。

盘点基线：2026-09-06，`b15485f32`。本次只核对实现、设计和已有测试，未运行构建、自动化测试或游戏。**“已有实现”不等于“已验收”，勾选表示验收通过。**

## 一句话完成边界

**内容作者能用本清单选定的目标和结构接入玩家任务、世界任务；玩家能在单机、多人及子世界中完成发现任务、推进目标、按规则处理失败、获取奖励和保存继续的完整流程，界面准确反映当前状态。**

初版交付物为现有双侧框架、可用的任务列表与详情页、两侧各一条可照抄的完整示例，以及本清单的验收记录。正式剧情的数量不作为任务系统完成条件。

| 范围 | 初版承诺 |
| --- | --- |
| 玩家侧 | 跟随玩家存档的个人进度；接取、提交、取消进入失败、目标重试；可重复任务由内容入口重新投放，多人中仍是各自的个人任务 |
| 世界侧 | 跟随世界存档的共享进度；多人状态和操作由主世界服务器授权 |
| 单机 | 两侧都能完成完整流程，包括进出子世界后的继续游玩 |
| 多人 | 两名玩家可独立推进个人任务、共同推进世界任务；加入、重连和正常领奖可用 |
| 多人子世界 | 玩家分别位于主世界、子世界时，共享进度、操作请求和奖励发放仍可用 |
| 内容范围 | 使用下列可用 Objective、顺序/并行/任选/分支结构；保留玩家任务/目标奖励与世界任务完成领奖，不要求增加新的剧情或玩法系统 |

快速收尾的具体取舍：世界任务的多人整任务重试补齐；玩家侧沿用“取消即失败”，重新获取由内容入口移除旧任务并创建新实例，不新增通用整任务重试按钮；世界目标内奖励、未完成的使用物品目标、任务树和星级留到后续。

## 必须通过的功能清单

### 任务流程

- [ ] **F01 玩家任务完整流程。** 任务能进入可接取列表，接取后仅推进本人的目标；自动完成与手动提交遵守任务配置；完成后发放奖励并进入正确的历史状态。已有实现，待验收。
- [ ] **F02 世界任务完整流程。** 未满足条件时保持锁定，满足条件后自动进入进行中，完成条件满足后进入已完成；任务失败后不再继续收集进度。多人中各端最终状态一致，权威状态转换和游戏副作用由主服决定。生命周期已有实现，主服授权边界需收尾核对。
- [ ] **F03 现有目标可用。** 下表列出的内置目标都能在其适用侧正确收集进度、完成、停止监听和恢复；事件累计型目标只在规定的活动期间收集进度，历史计数和背包持有量模式按各自规则判定。已有实现，逐类验收。
- [ ] **F04 目标组合可用。** 顺序目标依次推进；并行要求全部完成；任选满足一项即可；分支选中后只推进所选分支，其他分支不会继续影响结果。只验收现有容器能表达的组合。已有实现及结构测试，待验收。
- [ ] **F05 两级限时准确。** 任务计时与目标计时各自生效；未激活目标不计时；目标在同一更新时间片内的完成判定优先于目标到期判定。目标超时只冻结该目标，任务级到期才按任务规则失败。已有实现及计时测试，待验收。
- [ ] **F06 失败、取消与重试有明确结果。** 玩家任务取消/整任务到期后进入 Failed，不宣称自动回池；可重复任务通过内容入口移除旧任务、创建并接取新实例。两侧可重试的超时目标只重置自身，保留其他目标、分支选择和任务总计时，玩家侧还保留目标奖励领取标记。可重试的失败世界任务在单机、多人和子世界都能整任务重试，重复请求不能重复重置。目标重试已有实现；玩家重新获取示例待整理，世界任务的多人整任务重试需补齐。
- [ ] **F07 奖励规则完整。** 玩家任务与目标奖励按现有规则发放，同一实例的重复提交/目标重试不会重复发奖；内容入口重新投放的新任务按新一轮任务处理。世界任务完成后每个符合领取规则的玩家能从详情页领取一次，正常连接时物品实际到账，重复点击或重复请求不重复发放。存档后领取记录保留。初版不使用世界目标内奖励，沿用下方已确定的身份和断线限制。

### 存档与联机

- [ ] **F08 保存后能继续。** 对进行中、分支已选、目标超时、任务失败、已完成未领奖和已领奖状态保存退出，再加载后状态、累计进度、计时及领奖记录恢复；背包/环境派生进度按当前游戏状态重算。玩家数据与世界数据归属正确，切换角色/世界不串任务；玩家完成即发奖，不要求玩家侧存在单独的“未领奖”状态。已有持久化实现，待验收。
- [ ] **F09 多人共享状态一致。** 两人共同贡献世界目标，服务端只接受当前有效目标的贡献；任务与目标切换、操作结果同步到其他客户端；中途加入和重连能取得当前快照，过期操作不能改写新状态。已有同步实现和包/管理器边界测试，待实际联机验收。
- [ ] **F10 子世界完整流程。** 主世界与子世界分别有人时，两侧个人进度按归属保存，世界目标贡献能汇总，重试请求能返回权威结果，奖励发到玩家实际所在世界；进出子世界后能继续操作。已有转发和奖励授权机制，必须实际验收，不能用数据包单测代替。
- [ ] **F11 专用服务器与重新加载可用。** 专用服务器能加载任务系统并处理任务，不访问客户端图形服务；退出世界、重新进入及模组卸载重载后没有重复订阅导致的重复计数或旧界面状态。已有客户端隔离与卸载处理，待运行时验收。

### 玩家界面

- [ ] **F12 找到需要的任务。** 侧栏可打开/关闭任务面板；全局列表、来源入口及状态/类型筛选符合现有规则。默认排序为进行中、可接取、已完成、已失败、锁定；空列表可正常操作。已有实现，待验收。
- [ ] **F13 看懂当前任务。** 详情展示名称、描述、目标进度、分支状态、剩余时间和奖励；`Visible = false` 的任务不列出，非空白 Hint 按现行规则遮蔽详情，不泄露目标与奖励。任务图标缺省时有可用显示。已有展示适配与文字目标列表，待验收。
- [ ] **F14 操作与当前状态一致。** 接取、提交、取消、重试、领取奖励只在允许时出现并有效；取消确认可撤回；目标重试通过对应沙漏触发。旧界面条目、已失效玩家任务实例和重复点击不能越过领域校验。已有 Action 入口及相关测试，待验收。
- [ ] **F15 界面及时更新。** 打开面板立即读到最新状态；面板开启期间，进度、计时、分支、按钮、奖励领取状态随变化更新；切换选择和筛选后不显示其他任务的旧详情。已有事件刷新机制，仍需逐项检查列表、详情及非选中条目。
- [ ] **F16 提示和基本显示可用。** 任务状态提示、NPC 目标标记与实际状态一致，目标超时/完成后不再误提示；长文本和多奖励可滚动查看。窗口尺寸、分辨率或 UI 缩放变化后，仍能阅读和操作。普通玩家看到的按钮、状态和基础提示具备中英文文本；未接线的占位入口收起。需界面验收及收尾修正。

### 内容接入与交付

- [ ] **F17 内容作者可以照例接入。** 整理玩家侧、世界侧各一条可运行的完整示例，说明获取/解锁方式、目标组合、限时重试、完成奖励和保存恢复；列明两侧差异和不支持的组合。复用现有样例和素材即可。已有调试任务，需整理接入说明并实际跑通。
- [ ] **F18 发布范围清晰。** 正常入口不暴露调试任务或未完成的任务树/星级功能；需要保留的实验内容按仓库规则通过功能开关隔离。初版清单、当前设计和旧 TODO 的指向一致，未完成的新需求归入后续版本。需整理。

### F03 的目标范围

先以两侧现有目标集合为边界，不要求为了“对称”给另一侧补同名目标。

| 侧别 | 本版需验收的现有目标 |
| --- | --- |
| PlayerSide | `KillNPCObjective`、`CollectItemObjective`、`ConsumeItemObjective`、`ExploreObjective`、`TalkNPCObjective`、`GiveItemObjective` |
| WorldSide | `WorldKillNPCObjective`、`WorldCollectItemObjective`、`WorldConsumeItemObjective`、`WorldExploreObjective`、`WorldReachObjective`、`WorldTalkObjective`、`WorldGiveObjective` |

共同检查：数量/条件判定正确；提交物品只扣应扣的数量；取消、完成、超时后不继续扣物品或累计事件进度；恢复后订阅与计数不重复。世界目标另检查来自主世界和子世界的贡献是否按该目标当前设计汇总。

需要写进接入说明的差异：玩家击杀目标支持历史计数/独立计数，收集支持拾取累计/当前持有量，探索同时覆盖到达环境和环境内移动；世界收集目标按“任一玩家达到数量”判定，不能误写成全员背包数量相加。`UseItemObjective` 标记了禁止使用的 `Obsolete`，不在初版目标集合内。

## 沿用的规则与明确不做的内容

### 初版沿用的现行约束

- 玩家任务仍按定义名判重，不承诺同定义多个实例同时存在。取消进入 Failed，`Reset()` 清进度但不改变状态；本版可重复体验由内容入口移除旧任务再创建新实例实现，不等同于自动生成日常任务或通用整任务重试。
- 任务类型是显示与筛选标签。存在 Daily、Achievement、Challenge 标签，不表示初版要实现日常刷新、独立成就系统或挑战调度器。
- 只支持现有节点 API 的结构；不承诺任意深度嵌套、循环图或跨任务图编辑。
- 世界奖励以 Ordinal 精确比较的玩家名记录：同名共享记录，改名视为新名称，完成后加入的玩家可领取。
- 世界侧初版只承诺任务完成后的整任务领奖，目标内奖励不用于正式内容或作为后继目标的必需前置；玩家侧已有目标奖励继续验收。
- 世界领奖沿用当前“授权后记录即生效”的规则，不增加 pending、确认、重试补发或记录回滚。授权后断线可能未收到物品且无法再次领取；这项已记录限制不在本次收尾中重设计。正常连接下的未到账、重复发奖仍是阻塞问题。
- 不要求重做既有存档格式；已有兼容分支应保留并验证，不扩展为任意历史版本、任务定义重命名或目标结构变更的通用迁移系统。

现行设计参考 [QUEST_SYSTEM_DESIGN.md](QUEST_SYSTEM_DESIGN.md)。本清单明确采用玩家取消的当前实现，提出补齐世界任务的多人整任务重试，并缩减世界目标内奖励承诺；设计中的对应表述需在收尾时对齐。

### 后续版本，不阻塞初版

- 可视化任务树、树形布局及交互编辑器。
- 任务星级、难度模型、界面主题解锁、图标轮播增强及额外视觉效果。
- `UseItemObjective`、新的任务目标类型、入侵/事件系统集成、全伤害贡献统计等扩展条件。
- 日常刷新、随机任务生成、同定义多实例、共享个人任务/组队任务新规则。
- 任务追踪 HUD、地图导航、搜索、收藏、排序配置等新增入口。
- 玩家侧通用整任务重试按钮；世界目标内奖励、阶段物品回收、奖励账号身份升级、可靠补发协议与离线奖励。
- 新的监听/带宽优化、领域层合并或展示层重构；只有已复现的卡顿或功能错误影响验收时才纳入必要修正。
- 完整主线剧情、大量正式任务内容及新的美术素材。

这些是范围排除项，不意味着当前都存在对应需求或实现。已有入口若会误导玩家，应按 F18 收起后再发布。

## 修正点如何归类与安排

新增问题记录使用：`关联 F 编号 / 复现步骤 / 期望结果 / 实际结果 / 是否阻塞初版`。例如“目标超时后 NPC 仍有感叹号”归 F16，“重试重置了其他目标”归 F06，“新增任务星级”归后续版本。

判定规则：妨碍任务推进或恢复、损坏存档、错误扣物品/发奖、破坏共享进度、隐藏关键信息或让必要操作不可用，均阻塞对应功能；符合已列明限制的情况按限制处理。新增玩法、表现升级或不影响操作的细节不自动升为初版要求。

推荐执行顺序：

1. 处理失败后无法继续、进度/存档错误、扣物品/奖励错误及联机/子世界问题，优先补齐世界任务的多人整任务重试。
2. 逐类验收已有目标与结构，修复能够复现的问题。
3. 完成最小 UI 收尾：刷新、操作、基础文本、缩放和占位入口收起。
4. 整理两侧接入示例和文档，在最终代码版本跑完全部验收并冻结范围。
